# API reference

REST API of the Veltrixsecure Service Desk. Base URL: `/api/v1` (for example `http://localhost:5000/api/v1`). All endpoints except `/health` and the sign-in / password-reset endpoints require a session.

## Conventions

### Authentication

`POST /auth/login` with `{ "email", "password" }` sets an HTTP-only, `SameSite=Lax` session cookie (`vlx_session` by default; `Secure` when `COOKIE_SECURE=true`). The cookie holds a signed JWT (HS256) with the user id and a token version. Every request re-checks the account status and token version in the database, so deactivating a user, changing a password or calling `/auth/logout-all` ends existing sessions immediately.

Browsers must send the cookie (`withCredentials: true` / `credentials: 'include'`).

### CSRF header

Every `POST`, `PUT`, `PATCH` and `DELETE` must send `X-Requested-With: XMLHttpRequest`. Browsers cannot add this header cross-origin without a CORS preflight, and CORS only allows the origins in `FRONTEND_URL`. Requests without it get `403 CSRF_CHECK_FAILED`.

### Response envelope

Success:

```json
{ "success": true, "message": "Ticket created successfully", "data": { }, "meta": { } }
```

`meta` is present on paginated lists: `{ "page": 1, "limit": 25, "total": 488, "pages": 20 }` (ticket lists also include `counts` per quick view; task, asset and KB lists include `kpis`).

Error:

```json
{ "success": false, "message": "Close all 2 open task(s) before resolving this ticket.", "errorCode": "INVALID_TRANSITION", "requestId": "9f1c..." }
```

Validation errors add `details.fields`, a map of field name to message. Raw database errors, SQL and stack traces are never returned; they are logged with the `requestId`.

| Status | Meaning | Typical errorCode |
|---|---|---|
| 400 | Invalid input | `VALIDATION_ERROR`, `FILE_TYPE_BLOCKED`, `FILE_CONTENT_MISMATCH`, `WEAK_PASSWORD` |
| 401 | Not signed in / session ended | `UNAUTHORIZED`, `SESSION_EXPIRED`, `SESSION_INVALID`, `INVALID_CREDENTIALS` |
| 403 | Missing permission or CSRF header | `PERMISSION_DENIED`, `STAFF_ONLY`, `CSRF_CHECK_FAILED`, `ACCOUNT_DISABLED` |
| 404 | Not found, or not visible to this user | `NOT_FOUND`, `ROUTE_NOT_FOUND` |
| 409 | Unique value already used / record in use | `DUPLICATE`, `IN_USE` |
| 413 | Body larger than 1 MB | `PAYLOAD_TOO_LARGE` |
| 422 | A business rule blocked the action | `INVALID_TRANSITION`, `TICKET_CLOSED`, `NOT_PENDING`, `SCHEDULE_CONFLICT`, `MAJOR_ACTIVE` |
| 423 | Account locked after failed sign-ins | `ACCOUNT_LOCKED` |
| 429 | Rate limit | `RATE_LIMITED` |
| 500 | Unexpected error | `INTERNAL_ERROR` |

### Record identifiers

Records are addressed by their business number, generated by the server inside the creating transaction:

| Record | Format | Example |
|---|---|---|
| Incident | `INC-YYYY-NNNN` | `INC-2026-0001` |
| Service request / order item | `REQ-YYYY-NNNN` / `REQ-YYYY-NNNN.n` | `REQ-2026-0007.2` |
| Task | `TSK-YYYY-NNNN` | `TSK-2026-0031` |
| Problem | `PRB-YYYY-NNNN` | `PRB-2026-0004` |
| Change | `CHG-YYYY-NNNN` | `CHG-2026-0012` |
| Knowledge article | `KB-YYYY-NNNN` | `KB-2026-0003` |
| Asset | `AST-NNN` | `AST-035` |
| Major incident | `MI-n` | `MI-2` |

### Lists: search, filters, sorting, pagination

All filtering happens on the server. Example:

```
GET /api/v1/tickets?page=1&limit=20&search=vpn&status=In%20Progress&priority=1,2&sortBy=created&sortOrder=DESC
```

Ticket list parameters:

| Parameter | Values |
|---|---|
| `page`, `limit` | page number; page size up to 100 (default 25) |
| `quick` | `open`, `mine`, `unassigned`, `breached`, `risk`, `onhold`, `resolved`, `all` |
| `search` | matches number, summary, requester name, customer name |
| `kind` | `incident` or `request` |
| `status` | one or more states, comma separated |
| `priority` | one or more of 1-4, comma separated |
| `teamId`, `customerId`, `categoryId`, `problemId`, `assetId` | ids |
| `assignee` | agent id, `me` or `none` |
| `dateFrom`, `dateTo` | created date range (ISO dates) |
| `sortBy` | `created`, `updated`, `title`, `customer`, `priority`, `status`, `assignee`, `sla`, `number` |
| `sortOrder` | `ASC` or `DESC` |

Task, asset, request, KB, problem, change and audit lists accept the filters listed in `backend/src/validators/schemas.js`.

### File uploads

Multipart requests use the field `files` (up to `MAX_FILES_PER_UPLOAD`, each up to `MAX_FILE_SIZE_MB`). When a multipart request also needs structured data (new ticket, comment, catalog checkout), send it as JSON in a `payload` field. Every file is checked for a blocked extension (`.exe`, `.bat`, `.cmd`, `.msi`, `.scr`, `.vbs`, `.js`, `.jar`, `.com`, `.ps1`, `.dll` and a few more), an allowed extension, and content that matches the extension (magic-byte detection). Files are stored under random names outside any public folder; downloads go through `GET /attachments/:id/download`, which checks that the user may see the parent record (and, for files on internal notes, that they may read notes). Add `?inline=1` to preview images, PDFs and text in the browser.

### Rate limits

`RATE_LIMIT_MAX` requests per `RATE_LIMIT_WINDOW_MINUTES` for each signed-in session (requests without a session are counted per IP address, so colleagues behind one office IP do not share a limit), `LOGIN_RATE_LIMIT_MAX` failed sign-ins per 15 minutes, and 10 password-reset calls per hour per client. After `LOGIN_MAX_ATTEMPTS` wrong passwords an account is locked for `LOGIN_LOCK_MINUTES`.

## Examples

Create an incident:

```http
POST /api/v1/tickets
Content-Type: application/json
X-Requested-With: XMLHttpRequest

{ "kind": "incident", "title": "VPN drops after sleep", "description": "Since the update", "customerId": 1,
  "requesterId": 2, "categoryId": 4, "impact": 2, "urgency": 1, "channel": "Phone", "assignee": "auto" }
```

`201` returns the full ticket with its generated number, the calculated priority (from impact and urgency), SLA targets and the team chosen by the routing and automation rules.

Change state:

```http
PATCH /api/v1/tickets/INC-2026-0042/status
{ "status": "Resolved", "resolutionCode": "Fixed", "resolutionNotes": "Replaced the cable", "createArticle": true }
```

Placing a ticket On Hold requires `holdReason` and a `comment` (sent to the requester). Allowed moves: New to In Progress / On Hold / Resolved; In Progress to On Hold / Resolved; On Hold to In Progress / Resolved; Resolved to In Progress (reopen) / Closed. Closed tickets are read-only.

Order from the catalog (one request, several items):

```http
POST /api/v1/requests
{ "customerId": 1, "requestedForId": 2,
  "items": [ { "catalogItemId": 5, "values": { "user": "contractor.jones" } },
             { "catalogItemId": 10, "values": { "guest": "Visitor", "days": "2" } } ] }
```

Decide a CAB approval:

```http
POST /api/v1/changes/CHG-2026-0013/approvals/97/decision
{ "decision": "approve", "comment": "Low risk" }
```
